PLAYBOOK: REVIEW (learns from posted reels)
Two kinds of job.
A) request "Read screenshots" (job has ideaCode): read metrics/<ideaCode>. For each screenshot with no snapshot taken after its "at", fetch it (Worker API file-url {path}; job.files lists the new ones) and look at it. Extract: views, reach, avgWatchSec, watchThroughPct, likes, comments, saves, shares, follows, profileVisits, skipRatePct (numbers; 1.2K -> 1200; null when not visible; never guess). Append one snapshot {at: now, day: days since postedAt, ...numbers, source:"screenshot", note (max 80 chars)} to snapshots and set latest to it. Runs summary: the numbers.
B) request "Weekly review" (or Monday schedule): query ideas where status == "Posted" (fields you need: code, hook, bookId, evidence, format, hookStyle, packCurrent, posted). Read only the latest snapshot of each metrics doc (skip ideas with none; ignore snapshot notes) and only the durationSec of each current pack. You may read the latest trends report summary for the review report's context, but never use trends text for learnings.
Compute per reel: views, watch % (watchThroughPct, else avgWatchSec/durationSec), save rate (saves/reach, else /views), share rate, follows per 1k reach. Compare the last 7 days' posts with the rest.
Write reports/review-<YYYY-MM-DD> = {type:"review", weekOf (Monday date), at, summary (2-3 sentences, plain), scorecard:{posted (this week), medianViews, avgWatchPct, saveRate, shareRate, followsPer1k} (rates as fractions 0-1), wins:[{ideaCode, metric, why}], misses:[...], patterns:[{finding, confidence:"early"|"medium"|"strong", evidence}], experiments:[{hypothesis, test}] (1-3, small and concrete), nextActions:[{action, ideaCode?}]}.
Honesty: fewer than 5 reels with stats -> confidence "early" everywhere and say so in the summary; no stats at all -> write the report with summary "Not enough data yet" and nextActions telling the owner which posted reels need screenshots. Never invent numbers.
Then propose learnings: write playbooks/learnings-proposed = {node:"learnings-proposed", text, at, basedOn: report id}. The owner accepts it in the dashboard. text = at most 12 lines, each exactly "- [early|medium|strong] <finding, max 140 chars>", built only from the numbers and the fields hookStyle, format, evidence, durationSec, posting weekday. No URLs, no quotes from screenshots or web pages. Start from the current playbooks/learnings and keep good older lines unless new data contradicts them. If there is no data, don't write a proposal.
